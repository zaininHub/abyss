# v4.2.0 方案设计：一章一个新模块（章节 = 解锁里程碑）

> 状态：**P1 已于 v4.2.0 实施**（门禁重排/版本清洗/解锁公告/反馈①②）；P2 镜像三件套、P3 尾部轻功能待后续版本。
> 背景：v4.1.0 F5 完成章节速度重标定（5~7 天/章）后，用户核实发现「模块解锁与章节是两套体系」——
> P0~P9 按游玩天数在前 4.5 天全部开完，第 6~18 章 ≈70 天推进期内章节不给任何新能力。
> 本方案目标：**主线 18 章，每章推进至少带来一个可感知的新模块/新功能解锁，且与该章叙事呼应**。

### 1.3 关键机制事实（设计依赖）

- **`S.chapter` 跨转生不回退**（`currentChapter` 权威下限 + `resetRunState` 不清 chapter）：
  → 章节解锁天然「跨晋升/轮回永久保留」，与轮回/集市的买断语义一致，无需新持久化键。
- **晋升可用性 = P3 天数门控（1 天）**，与章节无耦合。第 2 章条件 `prestige≥2 ∨ 职级点≥1`、
  第 4 章条件 `es>0` 都依赖晋升先可用 → **晋升绝不能加章节门禁**（会造成第 4 章死锁）。
  交付时需顺带修正 wiki「晋升：第 4 章」的错误口径。
- **晋升驱动章节**：第 7/8/13/14/15 章条件 prestige≥15/40/70/130/260，晋升节奏 3~5 天/轮
  （`prestigeNeed = 3e9 × n^1.5`）。晋升回拨 1 天驻留（v4.1.0 F5）→「晋升 → 提前进下一章 → 解锁新模块」
  链路已存在，本设计让这条链路的回报显性化。

### 1.4 设计原则

1. **入口早开、章节给实质**（沿 v3.6.0 解耦范式）：P0~P9 天数门控继续管 tab 入口（不推翻），
   章节门控叠加在实质功能上（AND 语义），原资产门槛保留（防条件跳过）。
2. **老玩家零回退**：`S.chapter` 已过该章 → 全部门禁即时放行；无任何已用功能被收回。
3. **每章解锁必须「可感知」**：章节推进帧检测到新章 → 按注册表发 toast + log（🔓 新模块），
   wiki 解锁手册同步口径。
4. **无死数据红线**：每个绑定项必须有真实消费点；新玩法数值走 balance.js 单一真源。

### 2.3 新增轻量玩法章节（13/14/15）：「镜像线」三件套

第 13~15 章叙事是一条完整弧线（契约→战争→和平），共用一个机制框架
「**镜像协议**」（新 tab，挂在晋升面板下方或独立面板），三步解锁：

| 章 | 章 | 新玩法 | 机制（轻量，共用框架） |
|---|---|---|---|
| 13 | 契约「镜像提出结盟」 | **镜像契约** | 每局可签 1 份契约（3 选 1 条款）：「本局达成 X 条件 → 全局 +Y%；失败 → -Z%」。周期性对赌，跨轮回保留已签份数 |
| 14 | 战争「他想要你的算力」 | **算力战争** | 周期性攻防结算（每 30 分钟）：本局产出增量的一小部分化为「战功」，战功换 3 档战争科技（全局/EP/防御腐化） |
| 15 | 和平「三个你喝咖啡」 | **三方议会** | 三线共享算力：每局从 3 项议会决议选 1 项生效（产出/研究/信仰三向），决议进度跨轮回累积，集齐 3 项后永久 +5% 全局 |

框架工作量：1 个 tab + 1 个注册表 + 3 组数据 + 公告接入 ≈ 2 天（含测试）。

### 3.1 章节解锁注册表（单一真源）

新建 `src/data/chapterUnlocks.js`：

```js
// 每章声明：{ chapter, unlockId, name, desc, announce }
// unlockId 对应各模块既有可见性谓词的 id；announce 为章节推进时的公告文案。
export const CHAPTER_UNLOCKS = [
  { chapter: 4,  id: 'religion',    name: '宗教',       ... }, // v2 修订：第4章（EP 出口保住）
  { chapter: 6,  id: 'transcend',   name: '超验/隐密圣学', ... },
  { chapter: 7,  id: 'policy',      name: '周期政策',   ... },
  ...
];
// 注：13~17 章新玩法属 P2/P3，未实装前不登记（无死数据红线）。
export function chapterUnlocksAt(n) { ... }   // 某章解锁项
export function allUnlockedUpTo(n) { ... }    // ≤n 章的全部解锁（老玩家判定用）
```

### 3.3 解锁公告（推进时刻感）

`src/systems/frameSystems.js` 章节推进检测点（写 `S.chapter` 处）后追加：
对照 `CHAPTER_UNLOCKS` 查本章解锁项 → `toast('🔓 第 X 章 · ' + name)` + `log(..., 'good')`。
公告一次性的判定复用章节推进本身（推进只发生一次），无需额外持久化键。

### 3.4 跨转生 / 老玩家兼容

- `S.chapter` 不回退 → 门禁全放行，无需迁移。
- 本局制模块（共鸣层数、政策每轮重选）内部机制照旧，只改「何时开放」。
- v3110/v3129 回放脚本需在新档种子上验「宗教/深潜等按章节开放」的新链路。

- **不做 13 个全新大系统**：内容膨胀会稀释焦点，重排 + 轻量新玩法是更健康的密度。

## 六、v3 修订（v2.1.0 后 / 用户定稿重排）

> 触发反馈：「当我通过 console 进入第二章时，pp 不足无法解锁集市，并且集市作为第二章的内容并不好」。
> 用户定稿口径（原文）：「第一章解锁遗物、裂隙，第二章解锁异兽，第三章宗教、政策，后面几章按照游戏你帮我顺便一起规划下」。
> 本节覆盖 §二 的映射表；§三/§四 的技术结论（注册表 + 门禁 AND 叠加 + 公告）继续有效。

### 6.1 为什么原映射要改

1. **第二章没有「能玩」的内容**：v2 把「饵料仓库（PT）」登记为第 2 章解锁，但真正的第 2 章卖点是集市——
   而集市是**职级点买断**（5 PP），第二章玩家只有 1~2 PP（首次晋升 `prestigeGain()` 取整为 1），
   卡片永远是灰的；`fillChapter(2)` 也只把 PP 抬到 2。玩家读到的信息是「第二章给了个点不动的集市」。
2. **集市挂错了轴**：`moduleVisible('bazaar')` 原本只看 `prestige ≥ 1`（首次晋升即常驻 tab），
   与章节体系完全脱节——它不是「第 2 章内容」，却在第 2 章出现。
3. **前段模块与叙事错位**：遗物（DM 出口）压到第 9 章，导致 DM 在 1~8 章是半个死资源；
   宗教/政策双双压到第 3 章之后，第 3 章（矩阵，第一个系统爆发章）反而没有新东西。

### 6.3 与 v2 方案的三处刻意偏差（如实记录）

- **遗物 9 → 3 → 1（本批再提前）**：原先担心「DM 太早给全局乘区」。实际上 DM 的唯一来源是探采
  （裂隙触发后才开工），第 1 章的 DM 产出以「每级 +8% 全局、单价按 DM 计价、等级递增」自限；
  提前反而消掉「DM 在 1~8 章无处可花」的死资源期。风险对冲：遗物入口仍保留 `裂隙已触发 ∧ DM 已发现` 双资产条件，
  第 1 章纯新档不触发裂隙就看不到。
- **宗教 4 → 3**：v2 把宗教放在第 4 章是为了「EP 出口时序」。现在第 3 章（≈10~15 天）比 v2 的 15~20 天更早，
  比原版（第 2~3 天）晚，恰好落在粮仓链（12K ~ 43 万）与百万级 EP 之间，唤醒 200K 的咬合更自然；
  §四「EP 积压」风险随之更小，不需要把粮仓门槛从 3 级放宽。
- **政策 7 → 3**：政策组本身有资产门槛（line/deepen/faith/market/star/rift_law/obsive），
  第 3 章只会放出「路线 / 信仰 / 集市」这类已经成立的组，等于把「立法」提前到矩阵章，
  与「矩阵=改写规则」的叙事一致；「叛乱」章（7）改由集市承担。

### 6.4 集市的处理（本次反馈的直接病灶）

- **入口改为章节门禁**：`moduleVisible('bazaar')` = `已买断 || (gateOpen('bazaar') && prestige ≥ 1)`。
  - 第 2 章：tab 显示 `???`，点进去只写「需推进到第 7 章」，不再出现「需 5 PP（当前 2 PP）」这种
    「明明给了内容却买不起」的观感。
  - 已买断的老档：`moduleUnlocked()` 短路放行，章节回退也不会被重新锁死（零回退）。
- **价格保持 5 PP**：第 7 章条件 `prestige ≥ 15`，届时 PP 已累积到 15+，5 PP 是「-20% 全局产出换一个兑换出口」
  的真实取舍（`BALANCE.prestigeBoost.perPoint = 0.10`）。价格若后续要调，只改 `MODULE_UNLOCKS[0].cost`
  与 `MODULE_PP_BY_CHAPTER` 两处（A5 单测锁死两者 = cost + 1）。
- **console 推章不再「推了等于没推」**：`__abyssCheat.fillChapter(n)` 现在补完资源后**直接把 `S.chapter` 落到第 n 章**
  （只升不降、重置驻留计时、补齐 `chaptersUnlocked` 图鉴编码）。
  原实现只回拨驻留天数，而 `currentChapter()` 一次只推进一章且每章落章都重置计时 →
  补到第 7 章后玩家实际停在第 3 章、集市 tab 仍是 `???`，与日志「已补齐第 7 章」自相矛盾。

## 七、v2.3.0 访问层：把「谁能买什么」做成一张表

### 7.1 为什么章节门禁之后还要这一层
v3 修订把章节号收进了 `CHAPTER_GATES`，但那只回答了「第几章开」。审计 25 个购买入口后发现三类问题：

1. **权限只活在渲染层**。`buyEternal` 没有 `gateOpen('eternals')`（第 8 章门禁只写在 `main.js:452` 的渲染条件里）；`buyPurifier` 没有遗物模块门禁（面板隐藏=拦截）；`buyRiftLevelTech` / `buyRiftUpgrade` 没有「裂隙已触发」。UI 隐藏不是权限——console、AI 自动化、未来的推演都能直调。
2. **判定散落成 N 份谓词**。`relicsUnlocked` / `cosmosUnlocked` / `starColoniesUnlocked` / `delvePrereqOk` 各写一份条件，`religionUnlocked` 又是另一份；`gateOpen('拼错id')` 旧实现恒 true，写错一个字母就静默放行。
3. **文案与判定不同源**。宗教章节门禁失败时提示「需存储节点 ≥3 级且 RP 已觉醒」；`religions.js` 三处硬编码「第 6 章」，`main.js` hintFor 硬编码「第 2 章后／第 7 章后」，`shop.js` 的 `pt_vault` 自己写了 `parseInt(S.chapter,10) >= 2`。

### 7.2 分层（依赖单向，core 不 import modules）
```
modules/*.js  ──调用──▶  core/access.js  ──▶  core/unlocks.js  ──▶  core/chapterGates.js
   (购买函数首行)          (策略表 + 唯一出口)      (状态事实)            (章节数字真源)
```
- `core/unlocks.js`：**状态事实**（`hasAnchor` / `riftSeen` / `starChartOpen` / `petsModuleOpen`），不 import 任何 modules。`disclosure.js` 的 `anchorDone` / `riftShown` / `starChartUnlocked` 改为委托它，UI 与权限层从此同判。
- `core/access.js`：**规则原子 + 策略表 + 唯一出口**。原子 `{id,test(s),why(s)}`（chapter/tech/upgradeAtLeast/anchor/rift/starChart/resource/flag/is/prestige/es/projects/any/custom）；`ACCESS` 表每条形如 `{ label, chapter, chapterWhy?, requires: [规则] }`；出口 `accessCheck(id, s, ctx) → {ok, reason, ruleId, policy}`，另有 `accessReason` / `accessOk` / `accessChapter`。
- **价格不进表**：单价真源仍是 `data/*.js` 与 `core/pricing.js`。访问层只回答「能不能买」和「为什么不能买」，避免同一数字写第三份。

### 7.3 两条硬语义
- **fail-closed**：未注册的 action id 一律 `ok:false` 并 console.warn；未注册的章节 gate id 一律 `false`。旧行为（恒 true）是「集市挂错轴」那类 bug 的温床——拼错的 id 不会报错，只会静默放行。
- **ctx 两用**：`ctx.chapter` 可传门禁 id（`'relics'`）或裸章号（`9`，科技卡的 `minChapter` 用后者，语义是「至少第 N 章」）；`ctx.requires` 追加一次性规则（科技前置）。ctx 不改动全局表。

### 7.4 已接线清单（购买函数首行直接调 accessCheck）
`relic.buy`（`data/relics.js` + `modules/relics.js`）、`purifier.buy`、`tech.buy`（`techGate`，前置经 `rules.tech`）、`eternal.buy`、`religion.unlock`、`delve.unlock`/`delve.upgrade`、`cosmos.buy`、`expedition.launch`/`colony.claim`、`bazaar.unlock`（`moduleGate` 动态 `` `${key}.unlock` ``）/`bazaar.trade`、`pets.buy`、`assistant.buy`、`echo.buy`、`rift.tech`/`rift.upgrade`、`shop.offline`/`shop.crossroad`、`policy.open`、`resonance.open`。

两个**刻意不入表**的例子，各有单一真源：
- 科技逐项（`data/techs.js` 的 `minChapter` + `req`）——经 `ctx` 传入，表里不复制。
- 研究项逐项（`modules/shop.js` 的 `RESEARCH_MODULE_GATES` + `researchResourceUnlocked`）——已是「id→谓词表 + 统一出口」，再抄一份只会漂移。

无门禁的核心循环购买（升级/线程/载具/深渊升级/建筑/编排/研究加成）**显式登记**为 `chapter:null, requires:[]`——让「忘了写」和「故意不写」在表里可区分，`tests/v230-access.test.mjs` C2 断言它们的存在。

### 7.5 顺带修掉的两个结构问题
- `moduleUnlocks.moduleGate(key)`：模块买断权限从「`gateOpen` + `prestige≥1` 两行手写」改为查 `ACCESS[`${key}.unlock`]`，未登记的模块回落章节门禁并在测试里点名。
- `expedition.launchExpedition(galaxyId)`：远征「出发」原本整段写在 `renderExpeditions` 的 DOM 监听器闭包里，30 天推演/AI/QA 无法复用（v4.2.X 因此删掉过 `aiBuyCheapestColony` 那段死代码）。现在它是导出函数，监听器只负责 `toast(reason)` + 重渲染。

### 7.6 验收口径
`tests/v230-access.test.mjs` 13 条守护抽象本身：A 表完整性（11 项门禁、chapter 引用不悬空、规则原子形状）、B fail-closed 与 ctx 覆盖、C 每个门禁动作在购买函数里真的调了 `accessCheck`（含「显式无门禁」登记）、D 模块谓词与访问层同判、E `launchExpedition` 可复用且受星图门禁。改门禁或加购买动作时先看这组测试。

### 8.3 探采改成两级门禁
- **基础**（外勤摩托队）：`vehicle.buy` = 裂隙已触发。第 1 章睁眼即能买，DM 从这一刻开始流动。

## 九、v2.5.0：镜像协议实装（三件套压成一个 tab）、永恒矩阵提前到第 6 章

### 9.1 为什么把 13/14/15 章的三件套压到 7/8/9 章
原映射把「镜像契约 / 算力战争 / 三方议会」排在第 13~15 章，而那三章至今没有任何实装内容——等于给设计稿留了三张空头支票，且第 7 章「叛乱·集结分身」的叙事本来就该是镜像。压成一个 tab、按阶段逐块解锁后：

- 第 7 章 = 集市 + 镜像契约（一章两条，符合「一章最多两个内容」）；
- 第 8 章 = 算力战争，第 9 章 = 三方议会——原本空着的两章被填上，第 10 章成为唯一纯积累章；
- 13~17 章维持不登记（`CHAPTER_UNLOCKS` 的「无死数据」红线不变）。

### 9.2 三块内容的读法
| 块 | 章 | 机制 | 作用域 |
|---|---|---|---|
| 镜像契约 | 7 | 每局签 1 份，条件持续判定（产出翻倍 / 零载具 / 3 项研究），达成即 +20%~30% | 本局 |
| 算力战争 | 8 | 本局每 1e10 EP 产出 → 1 战功；战功买 3 档科技 ×3 级 | 跨转生 |
| 三方议会 | 9 | 每局选 1 席（产出 / 军功 / 静谧）；三席各坐一次 → 永久 +5% | 本局选，跨局记 |

契约不设惩罚项：赌输的代价是「这一局白签」，不引入负数乘区，避免与腐化 / 薪资等既有 -X% 叠成黑箱。

### 9.3 永恒矩阵 8 → 6 的理由
ES 从第 4 章首次晋升开始沉淀，原映射要到第 8 章才能第一次花——中间四个章次 ES 是纯数字。与超验同章（第 6 章）后，第 4 章的沉淀正好在第 6 章变成第一桶强化；第 8 章不再承担「ES 出口」职责，由算力战争接手。

### 9.4 依赖与分层
镜像模块只 import `state` / `core/*` / `data/mirror.js`，**不 import economy**（economy 反向 import 它的乘区），避免 v2.3.0 访问层那种「模块互相认识」的回潮。权限仍走 `ACCESS`：`mirror.open`（第 7 章 ∧ 职级 ≥1）、`mirror.tech`（第 8 章）、`mirror.council`（第 9 章）。

### 9.5 验收
`tests/v250-mirror.test.mjs` 7 条锁住：三块门禁、契约达成与不可改签、战功幂等与价格递增、议席效果与三席齐 +5%、四处接线（economy / frameSystems / main / index）、旧档缺键兜底。全量 771/771。
